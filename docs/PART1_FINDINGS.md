# NGIS-SYSTEM — Part 1 Analysis Findings (2026-11-14)

Written findings required by Part 1 of the TOP MASTER MVP PROMPT, produced before the
first implementation changes. Verified in a real browser (Chromium via agent-browser)
against the live Flask server at http://127.0.0.1:3000.

## 1. Architecture summary

- **Stack**: plain HTML/CSS/vanilla JS frontend (no framework), Flask backend (`server.py`,
  port 3000), SQLite academic store (`academic_store.py`), ~30 JSON data files in `data/`.
- **Portals**: `pages/admin` (51 files), `pages/principal` (24), `pages/teacher` (16),
  `pages/student` (13), `pages/shared` (12). No separate staff/parent portal — staff reuses
  admin pages; parent oversight lives in principal.
- **Shell**: `assets/js/layout.js` ("Layout Engine v3") renders sidebar + topbar from
  `data/sidebar_nav.json` (via `/api/nav/published`) per role. A byte-identical copy of
  layout.js exists at repo root (dead duplicate).
- **Design system**: `assets/css/design-tokens.css` is the declared single source of truth
  (brand green **#176B45**, Inter, radii, control heights, focus ring). Layered on top:
  `design-system.css` → `ui-cleanup.css` → `app.css`, with several `!important` override
  layers fighting each other (sidebar width declared 240/256/280px in three places).

## 2. Decisions locked (Part 2/3)

- **Green**: keep existing NGIS **#176B45** (present in every token layer; hover #125638,
  pressed #0D4029). The prompt's alternative #0F5132/#176B45 debate resolves to existing value.
- **Font**: **Inter** (OpenAI Sans is not licensed in the project). Inter was already the
  declared token but was silently overridden by Plus Jakarta Sans/Manrope in
  `design-system.css:31-34` — fixed. All hardcoded `Plus Jakarta Sans`/`Manrope`
  `font-family` declarations across `assets/css/*.css` replaced with Inter tokens
  (~30 declarations in app.css, design-system.css, hero.css, profiles.css,
  school-information.css, ui-states.css, admin-operations-control.css). Khmer font stack
  unified to Noto Sans Khmer → Khmer OS → Kantumruy Pro.
- **Semantic palette**: keep existing tokens (warning #D97706, danger #DC2626, info #0284C7)
  rather than the prompt's suggested #F28C28/#DC3545/#2563EB — they are already contrast-tuned
  and tint tokens exist (`--color-*-bg`, `--color-*-text-tint`).

## 3. Root causes of the "text disappears on click/hover" bug (Part 5)

1. **`ui-cleanup.css` §1.3 (lines 233-306)**: `background: transparent !important` applied to
   ALL buttons (including `html body [class*="btn"]`, specificity 0-1-2) — erased the green
   fill of `.btn-primary`, Tailwind `bg-[#176B45]` buttons, danger/warning buttons →
   **white text on white**. This was the master defect behind "Add User"/"Add Campus"/
   "+ Add Department" invisible buttons.
2. **`ui-cleanup.css` §1.6 (lines 693-715)**: forced `.btn-primary` text to `#176B45` (same
   color as its own background — green-on-green), load-order dependent.
3. **`app.css:486-494`**: `.nav-group-label-link:hover/.active` forced `color:#fff` with
   `background: transparent` — **sidebar group labels vanished on white sidebar**.
4. **`app.css:508-516`**: collapsible group labels → white text + white glow on hover.
5. **`app.css:941`**: `.side-foot-help` color #E1E9E3 (near-invisible on white).
6. **`app.css:915-927`**: nav counter pills used translucent-white bg + white text (washed out).
7. **`interactions.css:1124-1163`**: hover/click force-white repaint of cards whose text is
   white via *class* (latent; portals currently light).
8. Dark-theme sidebar white-text rules (`app.css:899-908`) conflict with the white sidebar
   forced by `design-system.css:1044` even in dark mode (latent; theme pinned light by
   `layout.js:929`).

**Fixes applied (root cause, not overrides)**: §1.6 filled-button colors → white; §11
"Semantic Button Variant Restoration" appended at cascade end with `html body` specificity
(primary/danger/warning/success/secondary/soft/ghost in all states + focus ring + disabled);
sidebar label/pill/footer colors → tokens; dropdown §12 global select standard.

## 4. Dashboard defects found and fixed (`pages/admin/admin.html`)

- `@media` CSS written as **plain text inside HTML** (rendered on the page) — moved into a
  real `<style>` block; queries were also logically inverted (`not all and (min-width:1024px)`
  → 4 columns only below 1024px). Fixed to standard `min-width` queries.
- KPI cards rendered into containers with **no grid class** (`.kpi-grid`/`.row-grid` sections
  were empty) — cards stacked 1-column. Wired `kpiCardsContainer`→`.kpi-grid`,
  `row2Container`→`.row-grid`.
- Dashboard error state always shown: code required `res.success` but `/api/admin/stats`
  returns `{data}` only. Fixed to tolerant contract check.
- **Fake institutional-ID generator** (`TCH-2026-XXX001`) in the Add User modal — removed;
  field now states ID is generated by backend on creation.
- Health fallback hardcoded `'Operational'` — replaced with `'Unknown'` (no fabricated status);
  health badge mapping extended (Operational/Connected/Ready/Enforced → success, Unknown →
  neutral); "Last checked" now uses the server probe timestamp.
- Combobox search fields were `<div class="select-search">` (dead search) — converted to
  real `<input type="text">`.
- Academic Monitoring renders a blank card when `data.cards` is null — now shows a concise
  empty state (backend has no workflow-summary aggregation yet; see §7).

## 7. Missing backend capabilities (Part 16 dependencies)

- `/api/admin/stats` provides real counts (students/teachers/staff/accounts/audit/pending)
  and `systemHealth` probes, but **no `cards`** (academic workflow summary) — Academic
  Monitoring needs a new aggregation (attendance/grades/timetables/exams statuses exist in
  separate endpoints: `/api/academic/admin/oversight`, `/api/timetable/monitoring/classes`).
- Health probes exist (`/api/health`, `/api/admin/operations/health`) — dashboard currently
  uses the `systemHealth` block from `/api/admin/stats`.
- Audit records available from `data/user_accounts.json` audit_log, `/api/admin/audit`,
  roles/CMS/nav audit files.

## 8. Dropdown findings (Part 9)

- Native selects get chevron+focus from `ngis-components.css:224-232` and
  `design-system.css:749-771`, but pages loading only `app.css` (e.g. teacher-submissions,
  teacher-departments) had no chevron; and unspecified cascade interactions stripped
  `background-image` in some contexts. **Fixed globally** with `html body select` standard
  (chevron SVG, 40px height, border, hover/focus/disabled states) appended to ui-cleanup.css.
- Custom combobox (`ngisDropdown`) used on admin.html — search inputs were dead `<div>`s (fixed).
- `.select-menu` has no fixed-position anti-clipping fallback (action-dropdowns do);
  z-index scale is inconsistent (60→1500). Deferred to Part 9 deep pass.
- ~46 pages use native selects; kebab menus exist in users/profiles/classes/campuses rows.

## 9. Loading behavior (Part 14)

- A global skeleton system already exists (`skeleton-system.css/.js` with `ngis-sk-*`,
  force-hiding legacy spinners) plus a second one (`ui-states.css` `ngis-skeleton-*`).
- Remaining issues: static skeleton shells with **no error state** (roles page, system-*,
  dictionary pages) can show forever if JS fails; `admin-dashboard-content.html` loading
  states are force-hidden by `skeleton-system.css:349-353` (`.cms-loading display:none`)
  leaving blank panels; several "Loading…" text-only rows (timetables, grades, calendars).
