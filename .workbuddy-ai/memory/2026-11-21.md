# 2026-11-21 — Frontend performance & layout audit (NGIS-SYSTEM)

## Root causes found
1. **Main-thread feedback loop (the "lag")**: `assets/js/action-icons.js` MutationObserver (whole document, childList+subtree) → rAF → `refresh(document)` → `hydrate()` rewrote `innerHTML` on EVERY `[data-ngis-icon]` unconditionally → new mutations → loop forever. Measured: 68 long tasks (60–150ms) in 4s idle, ~94 rAF/s, GSAP innocent (0 tweens).
   - Fix: idempotent hydrate (`el.__ngisIconStamp = key+':'+size` skip check).
   - Result: 0 rAF idle, 0 long tasks.
2. **ngis-search.js** observer loop amplifier: input with no parent never marked READY → needsWork() true forever. Fixed: mark READY on skip + try/catch in init().
3. **Hero overlap / crushed hero**: navbar.css (loaded via design-system.css @import chain — NOT a dead file) sets `.hero.hero-main .hero-body { padding-bottom: 24px !important }` with specificity (0,3,0), beating hero.css 84px and pages/*/css/responsive.css 76px (0,2,1). Hero height collapsed to 153px; deck overlapped greeting text.
   - Fix: removed pb from navbar.css (both base + ≤768px); restored responsive.css pb to 112px (matches user's wiped uncommitted fix).
4. **Unexpected centering**: ui-cleanup.css `div:has(> input[type=search])` arm forced ANY search-input container to `inline-flex` (shrinks to content, centers under centered parents). Removed arms. Also `.dash-overlap` (student.html) and `.hero-body` (portal-dashboard.css) had max-width:1280px + auto margins → centered decks/heros on wide screens; removed caps (old reference spans full width).
5. **GSAP 172KB + 6 plugins loaded eagerly on every page** via motion.js (injected by layout.js) though nothing uses it (all consumers guarded with CSS fallbacks). Made lazy via onGSAPReady→ensureGSAP().
