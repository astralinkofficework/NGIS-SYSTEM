## Server availability check
- Local NGIS server on port 3000 is healthy: 117/117 HTML pages returned HTTP 200, 12 concurrent page requests all completed in ~3 ms, 10 repeated `/api/health` calls returned 200, and the student dashboard rendered in the browser with 0 console errors.
- Found one real defect: `server.py` started Flask with `host='0.0.0.0'`, so `http://localhost:3000` failed when resolved to `::1` (Windows IPv6 loopback). Verified `curl -6 http://localhost:3000` failed while IPv4 worked.
- Patched `server.py` startup to bind a dual-stack socket (`host='::'` with `IPV6_V6ONLY=0` via a `BaseWSGIServer.server_bind` override). Validated on a temporary instance on port 3997: both `127.0.0.1` and `[::1]` returned 200 plus normal page rendering.
- The live server process did not auto-reload the change, so a manual restart is required for the fix to take effect on port 3000.
- Multiple `server.py` process trees exist (started 19:28), but only PID 15284 holds port 3000; no active port conflict was observed.
