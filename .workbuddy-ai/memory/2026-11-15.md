## Known architecture caveats (for future work)

- Anonymous demo browsing is unenforced; `X-Actor` header impersonation is a demo workaround, not production auth.
- Permission scope metadata (`global`/`assigned-campus`/`assigned-department`/`own-records`) is validated/stored but not applied to row-level data filtering.
- 74 of 100 registered permission pairs have no dedicated mutating-API binding; new APIs must be added to `API_BINDINGS`.
- The API gate fails open on unexpected exceptions (demo safety choice); production should fail closed.
