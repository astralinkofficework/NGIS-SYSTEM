- **New suite `tests/test_roles_permissions.py`** (37 tests, 5 groups):
  API contract / authorization / override validation / resolution & enforcement /
  frontend wiring. Snapshots `data/roles_permissions.json` in `setUpClass` and
  restores it before every test and in `tearDownClass`, so mutating endpoint
  coverage leaves no demo-data residue. Uses an injected second active `ADMIN`
  account (via `mock.patch.object(rp, '_identity_store', ...)`) to cover
  self-modification and privilege-chain rules, because the real identity store
  has only one ADMIN and it is `pending_activation`.

- **Bug fix — visibility vs access conflation** (`roles_permissions_api.py`,
  `/my-access`): previously `allowed = matched['allowed'] and not is_hidden`,
  so a visibility-only override silently became an access deny on the client
  gate while `server.py`'s `before_request` gate (which checks `allowed` only)
  still permitted the URL. Now `allowed` depends solely on `matched['allowed']`;
  `hidden` is returned separately. `Hide & Deny` still blocks because it sets
  `access: 'deny'`.

- **Bug fix — URL-encoded `ngis_actor` cookie** (found by live HTTP probe, not
  by unit tests): `auth.js`/`layout.js` write the cookie with
  `encodeURIComponent`, so `student@ngis.edu.kh` travels as
  `student%40ngis.edu.kh`. Werkzeug does **not** URL-decode cookie values, so
  the account lookup failed and enforcement silently disabled itself for every
  real browser session. Added `_actor_cookie()` in `roles_permissions_api.py`
  (`urllib.parse.unquote`) and used it in `_explicit_actor()` and
  `_session_actor()`; `server.py`'s `enforce_page_access()` now unquotes too.
  Regression tests now create cookies in the encoded browser form by default.
