## 3. PAGE LAYOUT — FOLLOW SCREENSHOT

Create the following structure inside the existing Timetable Builder page.

## 5. DRAG-AND-DROP INTERACTION — MOST IMPORTANT

Implement real drag-and-drop scheduling.

### Interaction A — Place a lesson

1. User selects a teacher.
2. The system loads that teacher's assigned classes and remaining periods.
3. User clicks and holds a lesson chip.
4. User drags the chip over the timetable.
5. Valid timetable cells become visibly highlighted.
6. The hovered cell displays a preview of the lesson.
7. User releases the chip.
8. The lesson is placed in that cell.
9. Remaining lesson count decreases immediately.
10. The action is added to Undo history.

### Interaction B — Move a scheduled lesson

1. User drags an existing timetable lesson.
2. The original cell becomes temporarily available.
3. Valid destination cells are highlighted.
4. User drops the lesson into another cell.
5. The system validates the move.
6. The original cell becomes empty.
7. The destination displays the lesson.
8. Teacher workload and remaining counts stay consistent.

### Interaction C — Swap lessons

If the destination cell already contains a lesson:

- Show a clear Swap option.
- Validate both resulting placements.
- Swap only if both placements are valid.
- Otherwise show the conflict and preserve the original schedule.

Never silently replace or delete a scheduled lesson.

### Interaction D — Remove a lesson

Allow users to:

- Select a scheduled lesson.
- Click Remove.
- Return the lesson to the remaining lesson pool.
- Update counts.
- Undo the removal.

### Interaction E — Cancel dragging

Support:

- Escape key
- Dropping outside a valid area
- Cancel action

The original lesson must remain unchanged after cancellation.

## 8. TEACHER VIEW AND CLASS VIEW

Provide two fully functional scheduling perspectives.

### Teacher View

Shows the selected teacher's weekly timetable.

A teacher must not be assigned to two classes at the same time.

The remaining lesson strip shows that teacher's unscheduled assignments.

### Class View

Shows the selected class's weekly timetable.

A class must not have two lessons in the same period.

The remaining lesson list shows subjects and teachers that still need scheduling for that class.

### Overview

Provide a compact overview of scheduling completion and unresolved conflicts across authorized classes.

All views must use the same underlying timetable records.

Switching views must not create duplicate schedules.

## 9. CONFLICT VALIDATION

Validate every placement and move.

Detect:

- Teacher double-booking
- Class double-booking
- Room double-booking
- Teacher unavailable
- Teacher exceeding configured workload
- Lesson exceeding required weekly periods
- Scheduling during breaks
- Scheduling outside school hours
- Scheduling on school closure days
- Scheduling during locked periods
- Cross-campus scheduling conflicts where travel or availability rules apply

If a move is invalid:

1. Do not commit it.
2. Restore the previous state.
3. Display the exact conflict.
4. Highlight the affected cells.
5. Offer a valid alternative if one can be calculated reliably.

Never allow the frontend to bypass backend conflict validation.

- Change teacher
